MoaPlay FIX72 결제 연동 설정

현재 연결 안내가 표시되는 이유
- 로그인용 카카오·Google 키만으로는 결제를 시작할 수 없습니다. 결제 가맹점 키가 별도로 필요합니다.
- PAYMENT_ENABLED=true, PAYMENT_PUBLIC_ORIGIN, 선택한 결제사의 가맹점 키를 모두 설정해야 결제 버튼이 활성화됩니다.
- FIX72 관리자 결제 연결 상태에서 빠진 환경변수 이름, 잘못된 키 형식, 테스트/운영 혼용 여부를 확인할 수 있습니다. 키 값은 표시하지 않습니다.
- 상태 화면은 서버 설정을 검사합니다. 가맹점 계약, API 권한, 등록 도메인, 키 유효성까지 결제사에 조회한 결과는 아닙니다.
- 이 소스에는 실제 가맹점 키가 포함되어 있지 않습니다. 가맹점 계약과 운영 키 없이 실제 결제를 활성화할 수 없습니다.

운영 서버에서 설정하는 순서
1. 결제 가맹점 계약을 완료하고 결제사 개발자센터에서 운영 키를 발급받습니다.
2. MoaPlay 서버를 실행하는 호스팅의 환경변수에 아래 공통 설정과 사용할 결제사의 키를 저장합니다.
3. 서버를 재시작/재배포한 뒤 관리자 결제 연결 상태를 새로고침합니다.
4. 해당 가맹점의 허용 상품, API 권한 및 반환 도메인을 확인한 후 실제 모바일/PC 환경에서 승인·취소·잔액 반영을 확인합니다.

공통 필수 환경변수
NODE_ENV=production
PAYMENT_ENABLED=true
PAYMENT_PUBLIC_ORIGIN=https://relay-server-production-5386.up.railway.app

PAYMENT_PUBLIC_ORIGIN은 실제 사용 중인 MoaPlay 서버 주소로 맞추세요.
경로, 쿼리, URL 사용자명/비밀번호가 없는 HTTPS origin만 허용합니다.
위 예시의 서버를 사용하지 않는다면 실제 배포 주소로 교체해야 합니다.

카카오페이
KAKAOPAY_CID=<운영 가맹점 CID>
KAKAOPAY_SECRET_KEY=<운영 Secret key>

- 카카오페이 개발자센터의 온라인 단건 결제 계약과 신 API 권한이 필요합니다.
- 카카오 로그인 REST API 키, JavaScript 키, 로그인 클라이언트 시크릿은 결제 Secret key가 아닙니다.
- 카카오페이 개발자센터의 플랫폼 > Web에 PAYMENT_PUBLIC_ORIGIN 도메인을 등록합니다. approval_url/cancel_url/fail_url에 사용되는 도메인입니다.
- 서버가 /online/v1/payment/ready로 주문을 준비하고, PC에서는 next_redirect_pc_url, 모바일에서는 next_redirect_mobile_url을 엽니다.
- 공식 응답의 online-pay.kakao.com 및 mockup-pg-web.kakao.com 결제창 주소도 허용합니다. 임의 kakao.com 서브도메인은 허용하지 않습니다.
- 승인 후 서버가 /online/v1/payment/approve 및 /online/v1/payment/order를 호출하여 주문, 회원, 거래 ID, 금액, 최종 승인 상태를 검증합니다.

토스페이
TOSSPAYMENTS_CLIENT_KEY=<live_ck_로 시작하는 API 개별 연동 클라이언트 키>
TOSSPAYMENTS_SECRET_KEY=<live_sk_로 시작하는 같은 상점의 API 개별 연동 시크릿 키>

- 토스페이먼츠 가맹점 및 토스페이 사용 계약이 필요합니다.
- 현재 연동은 SDK v2 payment().requestPayment(), CARD, DIRECT, TOSSPAY를 사용합니다.
- 공식 문서에서 이 SDK는 현재 '결제창(구버전)'으로 표시됩니다. 지원되는 API 개별 연동 키(ck/sk)를 사용하며, 주문서형·결제창형 위젯 키(gck/gsk)나 브랜드페이 전용 MID 키를 넣지 않습니다.
- 클라이언트 키와 시크릿 키는 같은 상점·같은 모드의 한 세트여야 합니다. 코드로는 키 접두어만 검사하며 같은 가맹점인지 여부는 결제사의 실제 응답으로 확인됩니다.
- PC와 모바일 모두 현재 브라우저에서 결제창을 열고, 성공 URL의 paymentKey/orderId/amount를 서버에서 검증합니다.
- 서버만 시크릿 키를 사용하여 /v1/payments/confirm 및 /v1/payments/orders/<orderId>를 호출합니다. 브라우저에는 결제창 초기화에 필요한 클라이언트 키만 전달됩니다.

테스트와 운영 구분
- 테스트는 별도의 서버·데이터 저장소·테스트 회원으로 수행합니다. NODE_ENV=test에서 테스트 키를 사용할 수 있습니다.
- 테스트 키는 기본 차단됩니다. NODE_ENV 미설정 서버에서도 허용되지 않습니다. 명시적으로 NODE_ENV=test를 설정하거나 비운영 서버에서 PAYMENT_ALLOW_TEST_MODE=true를 설정해야 합니다.
- 토스 test_ck_/test_sk_, 카카오 TC 계열 CID 또는 DEV Secret key는 테스트 설정으로 표시됩니다.
- NODE_ENV=production에서는 PAYMENT_ALLOW_TEST_MODE 값과 관계없이 위 테스트 설정으로 새 충전을 시작하거나 테스트 주문을 정산할 수 없습니다. 테스트 허용을 해제한 서버에서도 기존 테스트 주문은 정산되지 않습니다.
- 테스트 서버에서 생성한 잔액이나 결제 주문 데이터를 운영 저장소로 이전하지 마세요.
- 키 값이 있어도 결제사의 계약·승인·도메인 설정이 맞지 않으면 결제가 거절될 수 있습니다. 401/403 또는 잘못된 API 키 응답은 가맹점 연결 확인 안내로 표시됩니다.

서버 콜백
/pay/return/<orderId>/<oneTimeState>/complete
/pay/return/<orderId>/<oneTimeState>/cancel
/pay/return/<orderId>/<oneTimeState>/fail

Webhook: POST /pay/webhook/kakao, POST /pay/webhook/toss
- 웹훅은 주문조회 힌트로만 사용합니다. 웹훅의 금액이나 성공 상태를 그대로 적립하지 않습니다.
- 공급자 성공 URL에 도착하는 것만으로 충전하지 않습니다. 서버가 결제사에 최종 승인 상태를 재조회한 뒤 원장을 적립합니다.
- 승인 결과 확인이 지연되면 같은 결과 화면을 새로고침합니다. 새 충전을 반복하지 마세요. 승인 후 통신 단절·재시작·중복 콜백에도 같은 주문은 한 번만 적립합니다.
- 승인 요청 중에 취소 URL이 호출되면 취소 완료로 표시하지 않고 결과 확인 중으로 표시합니다.
- 진행 중인 주문이 남아 있을 때는 가맹점 계정/키 또는 PAYMENT_PUBLIC_ORIGIN을 임의로 바꾸지 마세요. 기존 주문 조회에 같은 가맹점 자격증명이 필요합니다.

유지되는 결제 규칙
- 충전 금액: 1,000~1,000,000 KRW 정수. 표시 통화 설정과 실제 결제 통화는 구분합니다.
- 기존 잔액, 원장, 상품 가격, 승인된 충전의 이벤트·업적 보상을 유지합니다.
- 결제 키를 APK, 웹 JavaScript, 공개 저장소에 넣지 마세요. 시크릿은 서버 환경변수로만 전달합니다.

개발 검증
npm ci
node scripts/test-fix72-payment-setup.js
node scripts/test-fix72-payment-setup.js --sqlite
node scripts/test-fix71-payments.js
node scripts/test-fix71-payments.js --sqlite

위 테스트는 모의 공급자 응답으로 설정 검증, 정상 결제창 주소, 위조 응답 거부, 중복 적립 방지, 저장 실패 복구를 검증합니다.
실제 가맹점 키를 이용한 운영 결제 검증을 대신하지 않습니다.
