GameConnect TLS 적용 안내 (FIX85)

1. 서버는 제공된 Dockerfile로 배포합니다. Node 22, OpenSSL, 시스템 인증서가 포함되어 있습니다.
   Railway에서는 GameWeb 디렉터리를 Root Directory로 지정하고 Dockerfile을 사용합니다.
   HTTP 관리자는 8080, 네이티브 TLS TCP는 3000을 사용합니다. 외부 TCP 프록시 포트는 기존 설정을 유지합니다.
   DATA_DIR=/data에 영구 볼륨을 연결하고 단일 복제본(HA_ENABLED=0)으로 실행하세요.

2. 첫 실행 때 DATA_DIR/connect-tls/ 안에 RSA 3072비트 개인 키와 인증서를 생성합니다.
   자동 생성 인증서는 game-connect.internal DNS SAN, 825일 유효기간을 사용합니다.
   DNS SAN은 내부 TLS 이름이며 공개 TCP 프록시 주소를 바꾸는 설정이 아닙니다.
   인증서 DER SHA-256 지문과 TLS 서버 이름은 관리자가 발급하는 A의 설정에 포함됩니다.
   인증서, 개인 키, DATA_DIR, 런처 발급 자료를 공개 파일에 포함하면 안 됩니다.
   재배포할 때 DATA_DIR를 보존하세요. 인증서가 사라지거나 지문이 바뀌면 서버는 인증을 중단합니다.

3. 외부에서 관리한 인증서를 쓰려면 CONNECT_TLS_CERT_FILE과 CONNECT_TLS_KEY_FILE을 모두 지정합니다.
   CONNECT_TLS_SERVER_NAME에 지정한 정확한 DNS SAN과 RSA 2048비트 이상 개인 키가 필요합니다.
   TLS 개인 키는 인증서와 일치해야 합니다. 만료되었거나 아직 유효하지 않은 인증서는 거부합니다.
   자동 생성/외부 인증서 모두 시작 시 같은 검증을 적용합니다.

4. 기본 자동 생성 인증서의 만료 시점은 관리자 연결 진단 API의 connection.tls.expiresAt에 표시됩니다.
   인증서 교체는 운영자가 서비스 중지, 데이터 백업, 기존 키/인증서와 connect-tls.sha256 백업 후 처리합니다.
   새 인증서를 지정하고 이전 지문 파일을 별도 보관한 뒤 재시작하여 새 지문을 확정합니다.
   이전 A에 들어 있는 인증서 지문은 바뀌지 않으므로 인증서 교체 후 새 A를 발급해야 합니다.
   누락된 인증서나 지문 변경을 무시하여 계속 실행하는 기능은 없습니다.

5. 네이티브 TCP 연결은 TLS 1.2 이상만 허용합니다. TLS 1.2는 ECDHE-RSA와 AES-GCM만 사용합니다.
   그 안에 기존 RSA-OAEP SHA-256 / AES-256-GCM 요청·응답 인증을 추가로 유지합니다.
   평문 TCP, TLS 1.0/1.1, 정적 RSA 키 교환, 변조된 GCM 태그, 재전송된 요청은 거부합니다.
   B의 메모리에서 정당하게 복호화된 데이터를 완전히 숨기거나 관리자 권한을 가진 PC의 분석을 막는 기술은 아닙니다.
   CRC64는 전송/파일 손상 검사용이며 악의적 변조 검증은 SHA-256, 인증된 통신, 서버 권한 검증이 담당합니다.

6. 관리 웹은 기존 HTTPS 역방향 프록시(예: Railway HTTPS)를 사용합니다.
   TLS로 전환한 네이티브 TCP와 관리 웹 HTTP 포트를 서로 바꾸면 안 됩니다.
   서버와 A/B는 같은 FIX85 버전으로 교체하고, A/B를 다시 등록한 다음 새 A를 발급하세요.
