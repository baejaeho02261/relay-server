Windows 격리 복구 훈련

Run_Recovery_Windows.bat은 원래 Windows 사용자·장치에서 기존 CNG/TPM 키로 서명한 뒤, 백업 복사본의 복구·키 교체·실제 A→B→O 실행을 같은 실행 ID로 확인합니다. 운영 서버와 원본 백업은 수정하지 않습니다. CI 키나 명령줄 Delphi 컴파일러가 필요하지 않습니다.

  1. RAD Studio IDE에서 GameConnect_Win64/tests/manual-ide/RecoveryDeviceProbe.dproj를 Win64 Release로 빌드합니다. 출력은 같은 폴더의 bin/RecoveryDeviceProbe.exe입니다.
  2. 정지한 서버의 완전한 백업과 해당 시점의 witness 스냅샷을 각각 준비합니다. 복사 witness는 물리적 독립성이나 가장 최신 운영 상태를 증명하지 않습니다.
  3. recovery-windows-input.example.json을 같은 tools 폴더에 다른 이름으로 복사하고 실제 경로와 값을 입력합니다.
  4. 기존 영속키를 만든 원래 Windows 사용자로 Run_Recovery_Windows.bat을 실행하고 입력 JSON 경로를 입력합니다. 관리자나 다른 Windows 계정으로 바꾸면 기존 사용자 키를 찾지 못할 수 있습니다.
  5. 같은 tools 폴더의 recovery-windows-…-results.json을 확인합니다. 실제 장치 또는 제품 실행에 실패하면 PASS가 나오지 않습니다.
입력실제 값
enrollmentId백업에 있는 ACTIVE 영속 장치키의 등록 ID, 소문자 16진수 64자리.
machineId해당 등록에 연결된 원래 PC 지문, 대문자 16진수 64자리. 실제 A/B/O도 같은 PC 지문을 증명해야 합니다.
provider기존 키에 맞게 SOFTWARE 또는 PLATFORM. PLATFORM은 실제 TPM 증명과 백업의 유효한 제조사 신뢰 설정을 통과해야 합니다. 소프트웨어로 자동 대체하지 않습니다.
artifacts A/B/O백업에서 이미 운영 중인 최종 등록 템플릿과 바이트가 같은 파일. 임의로 다시 빌드하거나 발급된 개인화 A를 넣지 않습니다. 파일 이름은 바꿀 필요가 없습니다.
allowIsolatedPcUnlocktrue일 때 복사본 안에서만 1회용 PC 제한을 해제하고 새로운 시험용 라이선스를 발급합니다. 사용한 기존 라이선스는 복원하지 않습니다.
verificationContextFile (선택)관리자 검증 이력 화면에서 받은 해당 명세의 검증 컨텍스트 JSON 절대 경로. 소스·최종 A/B/O·활성 명세가 일치하고 훈련이 통과하면 같은 결과 옆에 -verification.json이 생깁니다. 관리자 실기 보고 등록에 사용하며 CI 증빙이나 게시 승인은 아닙니다.

실행 결과 범위

원래 키는 열기·서명만 합니다. 교체키는 서버의 다음 세대 네임스페이스에 새로 생성하며, 기존 이름이 있으면 덮어쓰지 않습니다. 정상 종료와 파이프 EOF 오류에서는 프로브의 정리 경로가 훈련 중 직접 생성한 교체키만 제거합니다. 오류 발생 시 입력 파이프를 닫고 제한 시간 동안 이 정리를 기다린 뒤, 응답하지 않는 프로세스에 한해 강제 종료합니다.

교체키 제거가 확인되지 않으면 FAIL 및 UNCONFIRMED로 남습니다. 결과의 checks.replacementCleanup에는 실행 ID·공급자·네임스페이스와, 생성 응답을 확인한 경우 공개키 SHA-512만 보존합니다. 생성 응답이 소실되면 공개키 정보도 미확인으로 표시합니다. 이름만 같은 키를 재개방하여 자동 삭제하지 않으며, 원래 운영 키는 삭제하지 않습니다. Windows 강제 종료·전원 차단 이후에도 모든 로컬 흔적이 반드시 없어지는 것은 아닙니다.

서버 할당 라이선스 빌드는 평문 라이선스 키를 input.json에 기록하지 않습니다. 구형 수동 입력 빌드만 접근 제한 임시 파일을 사용하며 입력 완료·서버 소비 확인·실패 정리 시 제거합니다. 백업·witness 복사본과 실행 파일은 격리 서버의 임시 폴더에서 사용 후 제거합니다. 이 훈련은 원격 서버 전용 실행이 아니며, 결과 JSON은 관리자에게 제출할 검증 자료로 남습니다. CNG/TPM의 원래 비내보내기 장치키는 제품 인증을 위해 보존합니다.

기존 장치의 서명 검사는 실제 장치키와 서버가 새로 만든 A 컨텍스트를 사용합니다. 복구 전 제품 A/B/O 전체를 실행한 결과로 표시하지 않습니다. 복구 후에는 선택한 실제 A/B/O가 별도로 실행되고 세 역할 모두 교체키를 증명해야 합니다. 사용한 라이선스의 보존·재발급 거부를 확인하며, 과거 라이선스의 원래 서명된 redeem 요청 재생은 별도 NOT_RUN 항목입니다.

이 파일을 실행하기 전에는 Windows·CNG·TPM·실제 백업 검증 상태가 모두 NOT_RUN입니다. 프로브 빌드나 JSON 템플릿 생성만으로 실기 PASS가 되지 않습니다.
