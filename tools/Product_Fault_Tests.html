Windows A → B → O 제품 장애 테스트

기존 실행 파일로 실제 제품 경로를 실행하는 비 CI 진단 도구입니다. 컴파일·배포 승인·CI 증거·실제 GPU 드라이버 고장을 대신하지 않습니다. 이 소스 패키지 작성 환경에서 Windows 실행은 NOT_RUN입니다.

1. 빌드와 실행 준비

  1. Windows x64의 대화형 데스크톱 세션에서 Node, PowerShell 7 x64, OpenSSL 및 GameWeb 의존성을 준비합니다.
  2. RAD Studio IDE에서 일반 최종 Release A/B/O를 빌드합니다.
  3. GameConnect_Win64/tests/product-faults/의 GameLauncherFaultTest.dproj, GameConnectFaultTest.dproj, GameOverlayFaultTest.dproj를 별도로 빌드합니다. 이 파일에는 테스트 마커가 있고 일반 서버 게시 경로는 항상 거부합니다.
  4. tests/manual-ide/TlsReceiveProbe.dproj를 빌드합니다. 수신 경계 검사는 제품 세션 검사와 별도로 보고됩니다.
  5. product-fault-inputs.example.json을 복사하고 실제 절대 경로 및 버전을 입력합니다. 최종 EXE와 전용 테스트 EXE의 경로를 서로 바꾸지 마세요.
Run_Product_Fault_Tests.bat C:\path\product-fault-inputs.json
Run_Product_Fault_Tests.bat C:\path\product-fault-inputs.json /nopause

입력 JSON의 선택적 scenarios 배열로 아래 ID를 지정할 수 있습니다. 생략하면 17개 제품 시나리오를 선택합니다. 실행 파일 집합이 없으면 해당 시나리오는 NOT_RUN입니다. 서버의 원래 세션 만료를 기다리므로 일부 비정상 종료 검사는 수 분이 걸립니다. 시나리오 제한 시간은 450초입니다.

3. 격리 및 결과 판정

매 시나리오마다 새 localhost 서버, 전용 데이터 폴더, 임시 서명 키, 개인화 A, 한 번 쓰는 라이선스와 Windows Job을 만듭니다. 운영 서버·데이터·키를 읽지 않습니다. TLS 핀, 암호화, 서명, 기기 증명 및 서버 권한 검사는 실제 제품 구현을 통과합니다. 테스트 마커 허용은 전용 서버 어댑터 내부에만 있습니다.

결과 JSON은 최종/테스트 입력의 SHA-512와 실행 전후 불변 여부, 요청한 장애의 관찰, 부모 정리, 모든 서버 권한·런타임 비밀의 종료, 재사용 거부 및 소유 프로세스/폴더 정리를 기록합니다. 비정상 종료 뒤 남은 EXE 수와 테스트 도구의 최종 정리는 구별됩니다. 캡처한 요청 본문·키·티켓·로그·운영체제 경로는 공개 결과에 넣지 않습니다.

요청한 장애가 관찰되지 않거나 자식 프로세스가 남거나 권한/재사용 검증이 불완전하면 FAIL입니다. 필수 입력이나 별도 수신 프로브가 없으면 INCOMPLETE입니다. 실행이 없었던 항목은 NOT_RUN으로 남습니다.

4. 남아 있는 별도 검증

서명 EXE/JSON 교체 시나리오는 서버 배포 경계 검사입니다. 실행 직전 네이티브 파일 TOCTOU 전체와 물리 GPU/드라이버 제거는 별도 검사로 남습니다. SChannel/JSON/PE 수신 프로브의 성공도 A/B/O 세션 성공으로 바꾸지 않습니다. 일반 최종 Release의 CRC·비교·수동 검증 작업은 기존 Run_Manual_Windows_Tests.bat에서 수행합니다.

Run_Manual_Windows_Tests.bat에서도 lease 만료 시험을 선택할 수 있습니다. 입력 JSON에서는 faultArtifacts에 전용 테스트 A/B/O 절대 경로를 추가합니다. 일반 artifacts와 혼합하지 마세요. 선택적 verificationContext에는 관리자 화면에서 내보낸 대상 빌드의 검증 컨텍스트 JSON 경로를 지정합니다. 대상 최종 파일·소스 해시가 일치할 때만 -lease-verification.json을 만들어 관리자 화면에 전용 테스트 빌드 범위로 등록할 수 있습니다. 컨텍스트를 제공하지 않아도 로컬 시험 결과는 생성됩니다. 기존 V2 수동 검사 보고와 CI 선택 정책은 유지됩니다.

포터블 회귀 검사: node GameWeb/scripts/test-product-fault-tests.js, node GameWeb/scripts/test-product-fault-wire.js, node GameWeb/scripts/test-product-fault-tls-proxy.js. 이 결과는 Windows 실행 증거가 아닙니다. 자세한 영문 설명은 Product_Fault_Tests.md를 참조하세요.
