# 환경 설치 없이 확인하는 등록 파일 보안 검사

관리자 웹 → A/B/O 실행 파일 배포 → 서버 보안 · 배포 운영 → 등록 파일 보안 검사.

이 버튼은 현재 운영 중인 A/B/O를 서버에서 읽어 등록된 SHA-512·크기, 실제 배포 승인 서명, 철회 상태, PE/DEP/ASLR/CFG 구조를 검사합니다. A는 현재 템플릿과 서버 서명키로 임시 challenge를 서명·검증합니다. 고객별 A를 새로 발급하거나 사용 처리하지 않습니다. 개인키·접속 설정·파일 경로는 반환하지 않습니다.

검사는 수동 클릭에만 동작합니다. 파일별 64MiB, 합계128MiB로 제한하고 3초 이내 반복 요청을 거절합니다. 파일은 순차적으로 읽고 검사 버퍼를 지웁니다. 큰 파일의 동기 분석 중에는 짧은 서버 지연이 생길 수 있습니다. 정책, 라이선스, 발급 내역을 변경하거나 초기화하지 않습니다. 일반 관리자 접근 감사 기록은 남습니다.

CFG 요구를 편집한 경우 영향 미리보기에서 적용 불가능한 A/B/O 역할과 등록 ID를 확인합니다. 적합한 최신 미리보기가 있어야 정책 적용 버튼이 활성화됩니다. 편집 또는 서버 revision 변경 후에는 다시 검사해야 합니다. 이 기능은 CFG 코드를 EXE에 삽입하거나 기존 보호 요구를 자동 해제하지 않습니다.

## 이번 서버 수정

- 미사용 A에도 서버의 단조 시각 기반 유효기간을 연결합니다. 발급 시각 이전으로 서버 시계가 후퇴하거나 관측한 만료가 지나면 계속 사용할 수 없도록 처리합니다.
- 서버 정책 연산의 하위 평가기에서도 희소 배열, 상속 인덱스, getter와 추가 속성을 가진 인수를 거절합니다. 정상 Int32 계산 및 역할 연결은 유지합니다.
- 실제 파일 교체·위조 CFG 플래그·인증서 모양 데이터·서명 불일치·관리자 아닌 접근을 격리된 서버 테스트로 검사합니다.

## 완료했다고 표시하지 않는 항목

Windows 실제 A→B→O 실행·종료·삭제, Windows 게시자 신뢰 확인은 이 검사에 포함되지 않습니다. Authenticode 인증서 테이블이 존재해도 공개 CA 신뢰나 서명 암호 검증이 통과한 것으로 표시하지 않습니다. 자체 발급 서명과 Authenticode의 새 운영 형식은 아직 설계 단계이며 기존 동작하는 발급 형식을 변경하지 않았습니다.

제품 고유 업무 함수는 입력·결과·사용 위치가 지정되지 않아 임의로 추가하지 않았습니다. 서버 연산의 기존 입력 검증은 보강했지만 이를 실제 업무 이전 완료로 표시하지 않습니다. 검사 결과만으로 80점 또는 무취약성을 부여하지 않습니다. CI, 새 Windows 환경, Delphi 환경 구성은 추가하지 않았습니다.
