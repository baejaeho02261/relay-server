GameConnect · 서버 인증과 오버레이 개편

기준: 첨부 Game.zip. 기존 Windows 라이선스·A/B 배포 흐름을 유지하면서 인증 완료 후 오버레이 권한을 분리했습니다.

전체 수정 소스입니다. Delphi Win64 컴파일과 실제 Windows 화면 실행은 미검증입니다. 실제 운영 서버에 배포하거나 운영 데이터를 변경하지 않았습니다.

변경한 기능

영역구현
Windows 클라이언트TLS 레코드 쓰기 통합, DNS 작업 수 제한, 보수적인 잔여 시간 계산. 오버레이 API 45개를 기존 PEB 바인딩으로 연결하고 export 해시와 참조를 정적으로 검사했습니다.
관리자 보안로그인 시도 제한, 절대 세션 만료, 실제 로그인 세션의 CSRF 검증, 명시적 프록시 신뢰, 연결 및 업로드 정리. 기존 비밀번호 로그인과 1인 운영 유지.
Android전용 파일 55개와 QR 의존성을 제거했습니다. 기존 데이터는 백업 호환용 객체로 보존하며 구형 API는 거절합니다.
B 인증 완료서버 완료 트랜잭션에서 B 권한을 종료하고 별도 오버레이 권한을 발급합니다. 응답 유실 재시도를 지원하고 B의 작업 스레드·통신·개인키 소유 객체와 서버 임시 검증 상태를 정리합니다.
오버레이서버가 비실행 .dat 표시 데이터와 30초 이내 권한을 발급합니다. 별도 채널에서 갱신하며 라이선스/기기/배포/정책/서비스 상태를 서버가 확인합니다. 관리자 웹에서 표시 내용 변경과 권한 회수가 가능합니다.
관리자 화면 갱신배포·발급·설정 변경 성공 후 캐시를 무효화하여 최신 서버 상태를 다시 조회합니다. 기존 오래된 DOM 테스트 응답을 현재 API 계약에 맞게 정리했습니다.

구조와 한계

.dat는 실행 라이브러리가 아닌 표시 데이터입니다. B와 오버레이는 모듈·세션·자원 수명이 분리되지만, B의 Windows 호스트 프로세스는 화면 표시를 위해 유지됩니다. 로컬 화면 표시·입력·TLS·자신의 무결성 측정은 필요하며 기존 A→B 다운로드 파일도 유지합니다. 전체 로컬 실행/파일 생성 0개를 보장하지 않습니다.

오버레이는 일반 데스크톱 최상위 창이며 독점 전체화면 표시는 보장하지 않습니다. 서버 권한은 오프라인에서 무기한 유지되지 않습니다. PEB 정적 점검은 컴파일러/RTL을 포함한 최종 PE Import 전체 검사를 대체하지 않습니다.

적용

먼저 운영 DATA_DIR와 서명키/인증서/저널을 보존하세요. 서버 의존성을 설치하고 테스트한 뒤, RAD Studio 13.1에서 Build_Win64.cmd로 A/B를 전체 빌드합니다. 새 바이너리의 승인·해시·실제 Windows 시험 기록을 등록하고 새 A/B 조합을 게시하세요.

리버스 프록시를 사용한다면 WEB_ADMIN_TRUSTED_PROXY_IPS를 실제 프록시 주소에 맞게 지정해야 합니다. 자세한 순서는 ZIP 루트 README_적용안내.txt에 있습니다.
