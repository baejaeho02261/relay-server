서버 운영 작업함 · B KEY 입력 복원

SERVER_WORKSPACE 개선 유지 · B 콘솔 KEY 입력 복원 · UI game-console-92 · 이 문서는 로컬 관리용 안내이며 공개 웹 자산에 포함되지 않습니다.

적용 순서

이번에는 B의 콘솔 KEY 입력 경로를 복원했습니다. 서버 적용과 B 재빌드·재서명·운영 게시가 필요합니다. A의 실행 코드와 의존 유닛은 유지했으므로 현재 운영 A를 그대로 선택할 수 있습니다.

  1. 기존 운영 DATA_DIR, 서버 키, 라이선스, 등록 공개키, 기존 정상 배포물을 백업·보존합니다. 새 코드는 별도 폴더/깨끗한 소스 트리로 배포하세요. 덮어쓰기만 하면 삭제한 옛 파일이 남습니다.
  2. GameWeb을 먼저 적용합니다. 기존 데이터 디렉터리/볼륨 연결과 환경변수는 유지합니다. 새 작업 데이터는 서버 DATA_DIR/desktop-workspace/workspace.json에 저장합니다.
  3. Windows RAD Studio에서 GameConnect_Win64/GameConnect.dproj를 Win64 Release로 다시 빌드하고 기존 probe와 A→B 인계·KEY 입력·인증·갱신·종료를 시험합니다. 기존 Build_Win64.bat로 둘 다 빌드해도 되지만 다시 만든 EXE를 배포한다면 해당 EXE로 승인 서명을 만들어야 합니다. 이 환경에서 dcc64 빌드는 수행하지 않았습니다.
  4. 기존 배포 개인키로 새 EXE의 승인 JSON을 생성합니다. GameWeb/tools/Create_Approval.bat(독립 서명기)와 Check_Approval.bat를 포함했습니다. 운영자 도구이며 사용자 A/B에 배포하지 않습니다.
  5. 관리자 웹에서 라이선스 관리 → 새 버전 배포를 열고 A는 현재 운영 버전 유지, B는 새 EXE와 그 승인 JSON을 선택합니다. 버전은 승인 JSON에서 채웁니다. 후보 등록 → 선택 조합 검증 → 검증한 조합 운영 게시 순서입니다.
  6. 일회용 A 발급에서 이름만 입력하고 파일을 사용자에게 전달합니다. 라이선스를 먼저 만들거나 A에 배정할 필요가 없습니다. KEY는 별도로 발급해 전달하며, 사용자는 A 실행 후 B 콘솔에 KEY를 입력/붙여넣기하고 Enter를 누릅니다.

B는 정상 A 인계와 자기 이미지 검증 후 기존 KEY 입력 콘솔을 엽니다. 콘솔이 없는 이전 운영 B를 그대로 두면 복원되지 않습니다. 새 B를 게시해야 합니다. A 발급과 KEY 발급은 독립적이며, KEY가 없는 상태에서도 A를 먼저 발급할 수 있습니다. 사용된 A·KEY와 PC 제한은 초기화하지 않았으므로 기존 1회용 정책은 유지됩니다. 직접 B 실행/부적합 A/차단 PC 등 인계 검증 전 거절도 그대로입니다.

기존 필수 빌드 규격/시험 기록을 이미 켰다면 새 파일 해시와 A/B 조합에 맞는 실제 기준과 기록을 먼저 등록해야 게시/인증이 허용됩니다. 확인되지 않은 시험 PASS를 자동 생성하지 않습니다.

사용자 PC에 남는 범위

A/B는 사용자가 실행하는 일반 Windows 프로그램입니다. A의 기존 실행 흐름을 유지하고, B는 정상 인계 후 이전 콘솔로 사용자의 KEY를 받습니다. KEY 입력·붙여넣기·입력 버퍼 정리·콘솔 종료는 기존 구현입니다. 관리자 진단은 웹에 유지합니다. 새 로컬 KEY 파일·자동 로그인·레지스트리 승인 캐시·로그·자동시작·서비스를 추가하지 않았습니다.

필수 EXE, 실행 중 메모리, 기존 다운로드/인계에 필요한 파일은 남습니다. OS 페이징, 크래시 덤프, 운영체제 실행 기록까지 없다고 보장하지 않으며 이를 지우는 코드를 추가하지 않았습니다. 서버가 접속받지 못한 초기 로컬 오류는 원인까지 확정할 수 없습니다. 서버 로그에는 인증된 세션에 연결 가능한 요청 거절만 제한적으로 남기며 원시 토큰·개인키·메모리 덤프를 수집하지 않습니다.

이전 자동 인증 B와의 호환

이미 배포된 이전 자동 인증 B의 서버 처리와 저장된 배정 기록은 호환용으로 유지합니다. 새 B 콘솔에서는 자동 배정 표식을 거절하고 실제 입력 KEY만 사용합니다. 예전 A에 배정 기록이 남아 있더라도 새 B에서는 입력한 유효 KEY로 처리하며, 그 예전 KEY를 자동 소비하거나 사용 이력을 초기화하지 않습니다. 현재 운영 B가 아직 자동 인증 버전이면 새 B 게시를 안내하고, 실행할 수 없는 미배정 A를 발급하지 않습니다.

정리한 파일

루트에는 GameWeb과 GameConnect_Win64만 둡니다. 사용하지 않는 APK/회원 화면·라우트 모듈과 옛 보고서·패치·검사 manifest·로그를 제거했습니다. 아직 공용 데이터/마이그레이션/현재 코드가 참조하는 호환 모듈은 유지합니다. 기존 운영 APK 데이터는 삭제하지 않았습니다.

필요한 JSON/JS, 시험 벡터, 서명 도구, 현재 점검 자료는 GameWeb 안에 있습니다. 필수 라이선스/출처 고지와 TLS 적용 TXT는 유지합니다. 상세 변경·삭제·이동 목록과 시험 결과는 review.json입니다.
