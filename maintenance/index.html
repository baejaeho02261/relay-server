GameConnect · GameLauncher · Overlay

첨부 Game.zip을 기준으로 무결성 및 서버 인증을 확장한 소스입니다. 로컬 측정과 서버 최종 판정을 분리합니다.

실제 Windows/RAD Studio 13.1 전체 빌드와 Direct2D 화면 실행은 이 환경에서 검증하지 못했습니다. 해시 핵심은 FPC로 컴파일하여 검증했고, 서버는 Node 회귀 테스트로 확인합니다. 최종 테스트 결과는 review.json을 확인하세요.

영역구현
프로토콜GAME-CONNECT-4, profile 4, hashVersion 3. 파일·코드 SHA-512/XXH3-128 및 BLAKE3, 명시적 구버전 거부.
CRCECMA/NVME/JONES/XZ/WE/ISO, CRC32C, CRC16/ARC, CRC8/SMBUS. 역할별 측정과 누락 상태 보고, 승인 파일의 기준값과 서버 비교.
BLAKE3Hash·Keyed·Derive·XOF·incremental·표준 chunk tree. 멀티스레드 병렬 가속은 구현하지 않음.
인증서명된 challenge/nonce와 session/device/build/release/license 결합. 새 v4 실행은 authority 검증 필수. HMAC 인증 유지, 서버 보고 저장에 파생키 기반 BLAKE3 keyed MAC 추가.
OverlayO 전용 실행 프로젝트. 서버 발급·다운로드·부모 B 인계 후 실행. Direct2D 검정 배경/자체 체크박스, DirectWrite 텍스트. 일반 checkbox control·VCL/FMX 없음.
호환성서버 폴더 중복을 정리. 빠진 구형 APK 모듈 참조는 명시적 종료 경계로 처리하고 보관 데이터 유지. 기존 desktop 라이선스 소비 이력 보존.

적용 순서

  1. 운영 DATA_DIR과 서명키를 백업하고 점검 환경에서 먼저 적용합니다.
  2. RAD Studio 13.1 명령 프롬프트에서 GameConnect_Win64\Build_Win64.bat로 A/B/O 모두 Release Win64 재빌드합니다.
  3. 서버 코드를 적용하고 npm ci --omit=dev --ignore-scripts로 의존성을 준비합니다. 기존 권한 저장소 schema 1–4는 별도 서버 보관본으로 남기고 schema 5를 시작합니다. 구형 실행 ticket/session은 계속 사용하지 않습니다.
  4. 새 A/B/O를 등록하고 해시가 일치하는 릴리스 서명·빌드/시험 증거 및 DLL 기준값을 다시 등록합니다. O를 사용할 조합은 O를 먼저 게시한 뒤 Launcher를 발급합니다.
  5. Windows에서 정상/오류 KEY, 새 ticket, nonce 재사용, 폐기/만료/통신 차단, O 직접 실행 거부, B 종료 시 O 종료, 화면·입력을 검증합니다.

확인할 한계

CRC와 XXH3는 암호학적 인증 수단이 아닙니다. 클라이언트 측정값은 서명과 서버 기준값으로 검증되는 관찰값이며, 장악된 클라이언트의 진실성을 하드웨어처럼 보증하지 않습니다. 관리 문자열의 모든 과거 복사본까지 메모리 소거를 보장하지 않습니다. TLS SHA-256 지문과 기존 RSA/HMAC·장치 식별의 별도 SHA-256 용도는 명확히 유지합니다. 원본에 없던 KMAC을 구현했다고 표시하지 않습니다.

Overlay의 Option 1/2/3은 화면의 로컬 선택 상태입니다. 실제 기능 명세가 없는 게임 동작은 연결하지 않았습니다. O는 자신의 최상위 창을 사용하며 다른 프로세스 안에 삽입되지 않습니다.

cd GameWeb
npm ci --ignore-scripts
npm test
cd ..
python GameWeb/scripts/verify-source.py

source-manifest.json은 소스 일치 확인용 SHA-512 목록이며, 자체적으로 발행자 신뢰나 운영 릴리스 서명을 대신하지 않습니다.
