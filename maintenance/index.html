B 삭제의 범위

KEY 입력 전, 잘못된 KEY, 인증 실패 때 B 삭제는 시도하지 않습니다. 최초 성공 후 기존 방식으로 자기 실행 파일만 정리합니다. Windows가 실행 중 이미지의 삭제를 거부하면 파일을 남기고 인증 실행을 계속합니다. 모든 Windows·파일시스템에서 즉시 삭제 성공을 보장하지 않습니다. 신원·경로·해시 불일치는 기존처럼 오류로 처리합니다.

새 삭제 우회·헬퍼 프로세스·예약 작업·재부팅 삭제·기록 제거는 추가하지 않았습니다. 실행 중 코드, RAM, OS 기록을 지우는 변경도 없습니다. 삭제 여부를 서버에 자동 보고하는 새 프로토콜은 추가하지 않았습니다.

오버레이 상태

Win32 창을 몰래 추가하지 않았습니다. VCL/FMX 폼·버튼 없이 사각형만 표시하는 구성과 HWND 자체를 전혀 사용하지 않는 구성은 다릅니다. 일반 데스크톱 DirectComposition 출력도 소유한 HWND에 연결해야 합니다. 화면 DC 직접 그리기는 Win32 GDI를 사용하며 지속 표시와 화면 복구를 별도로 다뤄야 합니다. 이번 수정본은 그 선택을 대신하지 않습니다.

적용

GameWeb 서버 코드를 적용하고 재시작합니다. 운영 DATA_DIR·서명키·라이선스·공개키·배포 파일을 초기화하지 마세요. 관리자 웹 자산은 변경하지 않았으며 기존 UI revision game-console-92를 유지합니다. 새로고침하면 과거 정상 이벤트도 새 설명으로 표시됩니다.

B는 GameConnect.dproj를 Win64 Release로 재빌드하고 기존 개인키로 새 B의 approval.json을 만듭니다. 기존 서버 인계 규약은 바꾸지 않았으므로 게시 시 A는 기존 운영 파일을 선택할 수 있습니다. 공용 Game.Handoff 소스는 변경됐으므로 전체 빌드로 A까지 다시 만들고 배포한다면 그 A도 새 서명이 필요합니다. 빌드 규격·시험 근거 필수 정책을 켰다면 새 EXE 해시·조합에 맞는 실제 기록을 등록하세요.

운영 반영 전 Windows에서 잘못된 KEY 재입력, 정상 KEY 인증, 인증 후 B 파일 존재 여부, 계속 실행·갱신, Ctrl+C 종료를 확인해야 합니다.
