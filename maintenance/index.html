기준: GameConnect_GameWeb_OVERLAY_IDE_ONLY_FIX.zip + 이후 전달한 두 Pascal 수정 파일·리소스 + 사용자가 빌드 성공 후 제공한 해시. 서버와 기존 인증 흐름은 변경하지 않았습니다.

포함된 수정

파일반영 내용
Game.Overlay.Window.pasWinapi.Messages 추가, MsgWaitForMultipleObjects에 Handles[0] 변수 전달. 앞서 전달한 수정본과 바이트 단위로 동일.
Game.Overlay.Client.pas예약어 Inherited로 선언했던 배열 이름을 InheritedHandles로 수정. 앞서 전달한 수정본과 바이트 단위로 동일.
GameOverlayResources.res앞서 전달한 실제 바이너리 리소스 포함. 원본 manifest 및 버전 정보 유지.
Game.Overlay.Identity.inc사용자가 제공한 아래 상수 그대로 반영. 출하 include에는 생성 전 FATAL 중단문이나 하위 include 경로가 없습니다.
{ Generated from GameOverlay.exe in this source directory; do not edit. }
const OverlayExpectedSHA256 = '76f197016b0001626e0c55060dd06282ba54617b215e001d07fda40f1811f317';

이 값은 사용자가 제공한 값입니다. 사용자의 GameOverlay.exe는 업로드되지 않았으므로 이 환경에서 파일 해시를 대조한 것은 아닙니다. 이 ZIP에도 완성 EXE나 배포 개인키는 없습니다.

지금 성공한 상태를 유지해서 적용

현재 작업 폴더를 백업한 뒤 압축의 두 폴더를 같은 구조로 적용하세요. 빌드에 성공한 기존 GameOverlay.exe를 삭제하지 마세요. 새 소스 폴더를 사용한다면 그 EXE를 새 GameConnect_Win64 폴더로 복사합니다. 이 통합 작업만을 위해 오버레이를 다시 빌드할 필요는 없습니다.

기존 EXE와 위 해시가 일치하면 IDE에서 GameConnect.dproj를 빌드합니다. B의 기존 사전 빌드는 EXE의 존재와 해시를 검사합니다. 상수가 있다는 이유만으로 없는 EXE 또는 다른 EXE를 통과시키지 않습니다. 기존 프로젝트·BAT·PS1 이벤트는 이번에 변경하지 않았습니다.

오버레이를 수정하거나 다시 빌드하면 실제 파일 해시가 달라질 수 있습니다. 그때는 성공한 오버레이 빌드 후 기존 Update_Overlay_Identity.bat로 해시를 생성·대조하고 B를 다시 빌드하세요. IDE 후처리에서 해시 생성이 이미 완료됐다면 반복 실행할 필요는 없습니다. B만 빌드할 때 오버레이 생성 전 초기화 작업을 따로 실행하지 마세요.

새로 빌드한 B를 서버에 게시할 경우 그 B에 맞는 승인 JSON을 기존 배포 개인키로 생성해야 합니다. 현재 정상 EXE 자체를 계속 쓴다면 소스를 합쳤다는 이유만으로 승인 자료를 다시 만들 필요는 없습니다.

유지한 동작

A는 기존 다운로드·인계를, B는 KEY 콘솔·서버 인증·갱신과 오버레이 실행 신호를 담당합니다. 사각형은 별도 GameOverlay.exe에서 표시합니다. 기존 라이선스 성공 이후 B 파일 정리 시도, 서버 보안 판정·1인 관리자 정책·정상 실행 이력 표시 수정은 그대로입니다.

사용자에게는 기존 방식대로 웹에서 발급한 A와 해당 B에 맞는 GameOverlay.exe를 함께 전달합니다. 오버레이를 B에 합치거나 서버에 세 번째 파일 업로드 경로를 추가하지 않았습니다. 서버 JavaScript와 관리자 웹 실행 자산은 이번에 변경하지 않았으므로 운영 서버 재배포는 필요하지 않습니다.

검증 범위

review.json에 원본·개별 수정본의 해시, 보존 비교와 이번 실행 검사 결과를 기록합니다. source-manifest.json과 개발용 검사 기대값도 합쳐진 현재 소스에 맞췄습니다. 과거 이름의 maintenance 자료는 이전 단계 기록입니다.

전달 소스 일치 확인:
python GameWeb/scripts/verify-source.py

기존 GameOverlay.exe를 같은 폴더에 둔 뒤 실제 파일 해시까지 확인:
python GameWeb/scripts/verify-source.py --require-overlay

기본 검사에서 정확히 동봉한 사용자 제공 상수만 있고 EXE가 없으면, 소스 일치 여부와 EXE 미검증을 구분해 표시합니다. 실제 EXE가 있으면 기본 검사에서도 해시 불일치를 거절합니다. --require-overlay는 EXE가 없어도 실패합니다. 이 개발용 검사는 B의 실제 실행·빌드 검증을 약화시키지 않습니다.

사용자의 빌드 성공 보고와, 이 환경의 검사는 별개입니다. 여기서는 dcc64·RAD Studio·Windows PowerShell/BAT·오버레이 실행을 수행하지 않았습니다. 소스·패키지 일치와 정적 검사를 Windows 실행 성공으로 표시하지 않습니다. 운영 서버에 접속하거나 설정·라이선스를 변경하지 않았습니다.
