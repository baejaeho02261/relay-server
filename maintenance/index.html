서버 운영 작업함 · 사용자 A/B

SINGLE_OPERATOR 정상본 유지 · UI game-console-91 · 이 문서는 로컬 관리용 안내이며 공개 웹 자산에 포함되지 않습니다.

적용 순서

이번에는 A/B 소스가 바뀌었습니다. 이전 EXE와 승인 JSON을 그대로 쓰는 서버 전용 패치가 아닙니다.

  1. 기존 운영 DATA_DIR, 서버 키, 라이선스, 등록 공개키, 기존 정상 배포물을 백업·보존합니다. 새 코드는 별도 폴더/깨끗한 소스 트리로 배포하세요. 덮어쓰기만 하면 삭제한 옛 파일이 남습니다.
  2. GameWeb을 먼저 적용합니다. 기존 데이터 디렉터리/볼륨 연결과 환경변수는 유지합니다. 새 작업 데이터는 서버 DATA_DIR/desktop-workspace/workspace.json에 저장합니다.
  3. Windows RAD Studio에서 GameConnect_Win64/Build_Win64.bat로 A/B를 재빌드하고 기존 probe 및 실제 인계·인증·갱신·종료를 시험합니다. 이 환경에서 dcc64 빌드는 수행하지 않았습니다.
  4. 기존 배포 개인키로 새 EXE의 승인 JSON을 생성합니다. GameWeb/tools/Create_Approval.bat(독립 서명기)와 Check_Approval.bat를 포함했습니다. 운영자 도구이며 사용자 A/B에 배포하지 않습니다.
  5. 관리자 웹에서 라이선스 관리 → 새 버전 배포를 열고 A/B·공개 승인 JSON을 선택합니다. 버전은 승인 JSON에서 채웁니다. 후보 등록 → 선택 조합 검증 → 검증한 조합 운영 게시 순서입니다.
  6. 사용 전 라이선스를 발급하고, 일회용 A 발급에서 그 라이선스를 선택합니다. 해당 연결은 서버에만 저장합니다. 사용자에게는 새로 발급한 A만 전달합니다.

사용자 B의 키 입력창은 없습니다. 웹에서 배정되지 않은 실행은 승인하지 않습니다. 기존 발급 A를 새 B와 조합하면 자동 인증할 수 없으므로 새 A를 발급하세요. 사용된 라이선스/PC 제한은 초기화하지 않았습니다. 필요한 경우 기존 PC 차단 해제 경로를 이용하고 새 라이선스와 A를 발급합니다.

기존 필수 빌드 규격/시험 기록을 이미 켰다면 새 파일 해시와 A/B 조합에 맞는 실제 기준과 기록을 먼저 등록해야 게시/인증이 허용됩니다. 확인되지 않은 시험 PASS를 자동 생성하지 않습니다.

사용자 PC에 남는 범위

A/B는 사용자가 실행하는 일반 Windows 프로그램입니다. 콘솔/키 입력/관리자 진단 화면을 시작하지 않고 기존 인증된 인계 후 서버 배정 라이선스를 사용합니다. 자동시작·서비스·레지스트리 승인 캐시·새 로컬 진단 파일은 추가하지 않았습니다.

필수 EXE, 실행 중 메모리, 기존 다운로드/인계에 필요한 파일은 남습니다. OS 페이징, 크래시 덤프, 운영체제 실행 기록까지 없다고 보장하지 않으며 이를 지우는 코드를 추가하지 않았습니다. 서버가 접속받지 못한 초기 로컬 오류는 원인까지 확정할 수 없습니다. 서버 로그에는 인증된 세션에 연결 가능한 요청 거절만 제한적으로 남기며 원시 토큰·개인키·메모리 덤프를 수집하지 않습니다.

정리한 파일

루트에는 GameWeb과 GameConnect_Win64만 둡니다. 사용하지 않는 APK/회원 화면·라우트 모듈과 옛 보고서·패치·검사 manifest·로그를 제거했습니다. 아직 공용 데이터/마이그레이션/현재 코드가 참조하는 호환 모듈은 유지합니다. 기존 운영 APK 데이터는 삭제하지 않았습니다.

필요한 JSON/JS, 시험 벡터, 서명 도구, 현재 점검 자료는 GameWeb 안에 있습니다. 필수 라이선스/출처 고지와 TLS 적용 TXT는 유지합니다. 상세 변경·삭제·이동 목록과 시험 결과는 review.json입니다.

전체 서버 회귀 41개 중 35개 통과, 6개 의존성 부족으로 미완료. 새 서비스 30개와 실제 HTTP/TLS 12개 시나리오는 이 명령들에 포함되므로 중복 합산하지 않습니다. Chromium 12개는 실제 화면 JS + 모형 API/해시 입력 시험이며 Windows 실행이나 브라우저 WebCrypto 자체의 검증은 아닙니다. JS 230개 문법 검사는 통과했습니다.

실제 dcc64 컴파일·Windows 수명/ABI·운영 배포·전체 SQLite·장시간 부하는 미검증입니다. 작업함은 한 번 100개, 진행 중 100개, 보관 1000개 한도이며 자동 이력 삭제는 하지 않습니다. 파일 정리는 수동 미리보기/실행만 지원하고 참조 중 파일을 자동 삭제하지 않습니다.

이전 루트 audit/SOURCE_MANIFEST.json 대신 GameWeb/maintenance/source-manifest.json을 시험 기록 도구의 manifest 인수로 사용합니다. 실제 로그에서만 PASS를 기록하세요.
