# 사용자 정의 연산을 서버에서 호출하기

서버 정책 연결 v2의 사용자 정의 함수는 서버에 등록한 제한된 정수식입니다. 새 Native 클라이언트의 호출 API에서 함수 ID와 인수를 보내면, 서버는 현재 파일·정책·역할·기기·세션과 필요한 라이선스·무결성 권한을 확인한 뒤 결과 정수만 반환합니다. 함수 1은 내부 권한 검사 전용이며 외부 호출에 사용할 수 없습니다.

## 정책과 호출 지점

관리자 화면의 **서버 정책 연결 · Cozy v2**에서 A/B/O에 연결할 정책 JSON을 선택합니다. 각 사용자 함수는 고유 ID 2~65535, 인수 0~8개, Int32 정수식으로 정의합니다. 예를 들어 다음 함수는 두 입력의 합을 서버에서 계산하는 사용법 예제입니다. 실제 비밀값이나 업무 규칙을 포함하지 않습니다.

```json
{
  "version": 1,
  "functions": [
    {
      "id": 2,
      "args": 2,
      "body": {
        "op": "add",
        "left": { "op": "arg", "index": 0 },
        "right": { "op": "arg", "index": 1 }
      }
    }
  ]
}
```

제품 코드에서는 유효한 A/B/O 클라이언트 인스턴스의 `InvokeServerPolicy` 메서드로 이 ID를 호출합니다. 반환값은 업무 결과이며 서버의 세션·라이선스·게시 권한을 대신하는 승인 토큰이 아닙니다. 서버에 정책을 등록하는 것만으로 기존 Delphi 함수가 변경되지는 않습니다. 이전 로컬 계산을 새 호출로 바꿀 지점은 제품 개발자가 명시해야 합니다. 기본 정책에는 사용자 함수가 없으므로 함수 2를 자동 호출하지 않습니다.

연산은 검증된 정수식 IR만 지원합니다. JavaScript 실행, 임의 Delphi 번역, 파일·네트워크 접근 또는 클라이언트가 요청에 넣은 코드 실행은 지원하지 않습니다. 32비트 연산 규칙과 최대 단계 수는 정책 엔진의 기존 제한을 따릅니다. 인수와 결과는 인증된 클라이언트가 알 수 있으므로 입력·출력까지 숨기는 방식으로 설명하지 않습니다.

## 인증과 실패

각 호출은 현재 서버 정책 식별자, 함수 ID, 인수, 역할과 세션에 연결합니다. 일회용 도전값에 서명하여 요청을 확정하고, 만료·재사용·인수 변경·다른 역할·등록되지 않은 함수·폐기된 세션은 거절합니다. 권한은 호출 시 다시 검사하며, 서버 정책 바이트코드나 복호화 키를 반환하지 않습니다. 실패 시 클라이언트에서 같은 계산을 로컬로 우회 실행하지 않습니다.

서버 IR은 순수 계산이므로 호출 결과를 잃었다고 업무 변경이 실행된 것으로 간주하지 않습니다. 결제·파일 변경처럼 별도 부작용이 있는 업무 API로 확장하려면 해당 업무의 서버 권한과 중복 처리 규칙을 따로 설계해야 합니다.

## 운영 전 검증

새 Native 코드는 Windows/Delphi에서 다시 빌드해야 합니다. 이 개발 환경의 서버 회귀 검사는 실제 Windows 실행 성공을 뜻하지 않습니다. 이 문서의 소스 검사나 예제 호출은 최종 A/B/O 파일의 서명·Windows 시험·승인·명세 연결을 대신하지 않습니다. 최종 파일을 검증하기 전에는 새 고객용 배포 완료로 취급하지 않습니다.

## V1 입력·결과 소유권과 취소 연결

`SnapshotServerOperationArgs`는 함수 ID 2~65535와 최대 8개 Int32 입력을 검사한 뒤 독립 배열을 만듭니다. A/B/O 래퍼는 느린 무결성 보고에 들어가기 전에 이 사본을 만들고, 호출이 끝나면 `ClearServerOperationArgs`로 사본을 지웁니다. 원본 배열은 호출자가 소유하며, 스냅샷을 만드는 짧은 구간에는 원본을 동시에 수정하면 안 됩니다. 서버 호출 내부에서도 별도 사본으로 요청·인수 해시·서명 입력을 일치시킵니다.

A/B/O의 `InvokeServerPolicy`는 선택적인 취소 콜백을 받습니다. 기존 종료 상태와 이 콜백을 함께 검사하고, 무결성 측정·서명·전송·결과 반환 경계에 적용합니다. B는 현재 라이선스와 로컬 단조 시각의 lease를, O는 현재 인수·전달 상태와 갱신된 lease를 다시 확인합니다. 서버는 최종 연산 전후에 자신의 권한·등록 파일·정책·라이선스·무결성 조건을 별도로 확인합니다. 로컬 취소 검사는 서버 승인을 대신하지 않으며, 이미 정지된 프로세스의 스레드를 계속 실행시키는 기능도 아닙니다.

공개 정규 메시지 생성기는 역할, 세션·기기·정책 ID, 요청 ID, 함수 ID, 해시와 challenge 필드의 정확한 길이·대소문자·ASCII 문자 집합·정수 범위를 검사합니다. 임의 trim이나 대소문자 변환은 하지 않습니다. 클라이언트의 `ServerOperationCanonical`은 전달받은 binding이 같은 필드에서 직접 재계산한 값인지도 확인합니다. 유효한 V1 요청과 정규 메시지 바이트는 기존과 같습니다. 응답 숫자는 정규 십진 정수만 허용하고, 최종 취소 확인을 통과한 뒤 결과를 호출자에게 반환합니다.

## 명시적인 업무 연결 예제

`Cozy.Tests/Cozy.Security/Cozy.ServerOperations.Example.pas`의 `RunForA`, `RunForB`, `RunForO`는 함수 ID·입력·결과 소비 콜백·취소 콜백을 명시적으로 받습니다. 이전 `ComputeForA/B/O` 예제 시그니처도 유지합니다.

- A: 인증된 흐름에서 무결성·모듈 보고 이후, B로 Finish 하기 전.
- B: Redeem 이후 현재 라이선스가 살아 있는 동안 기존 API 작업 스레드에서.
- O: O claim과 부모 전달 확정 이후 기존 직렬 작업 스레드에서.

각 예제는 입력을 독립적으로 보관하고, 서버 호출이 성공한 후 취소를 다시 확인한 다음 결과 소비 콜백을 한 번 호출합니다. 실패하면 예외를 상위 작업 소유자에게 전달하며 결과 소비 콜백을 호출하지 않습니다. 새로운 백그라운드 스레드, 재시도, 로컬 계산 우회 또는 화면 출력은 추가하지 않습니다. 호출 소유자는 취소 후 작업에 합류한 다음 클라이언트와 콜백이 참조하는 상태를 해제해야 합니다.

이 코드는 컴파일 가능한 연결 예제입니다. 아직 지정되지 않은 제품 업무 함수를 자동으로 변경한 것으로 표시하지 않습니다. 실제 적용에는 다음 세 항목이 필요합니다.

1. 서버로 이전할 기존 함수와 소스 위치.
2. 입력 종류·범위와 반환값 의미.
3. 반환값을 실제로 사용할 제품 코드 위치.

현재 지정된 계약은 Int32 V1뿐입니다. 문자열·열거형 등의 새 형식은 업무 요구가 정해졌을 때 길이·정규화·서명 도메인·결과·예산을 별도 버전으로 설계합니다. 임의의 새 자료형이나 로컬 비밀 연산을 추가하지 않았습니다. 실제 Windows/Delphi 빌드·실행은 별도 확인이 필요합니다.
