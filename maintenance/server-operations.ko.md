# 사용자 정의 연산을 서버에서 호출하기

서버 정책 연결 v2의 사용자 정의 함수는 서버에 등록한 제한된 정수식입니다. 새 Native 클라이언트의 호출 API에서 함수 ID와 인수를 보내면, 서버는 현재 파일·정책·역할·기기·세션과 필요한 라이선스·무결성 권한을 확인한 뒤 결과 정수만 반환합니다. 함수 1은 내부 권한 검사 전용이며 외부 호출에 사용할 수 없습니다.

## 정책과 호출 지점

관리자 화면의 **서버 정책 연결 · Cozy v2**에서 A/B/O에 연결할 정책 JSON을 선택합니다. 각 사용자 함수는 고유 ID 2~65535, 인수 0~8개, Int32 정수식으로 정의합니다. 예를 들어 다음 함수는 두 입력의 합을 서버에서 계산하는 사용법 예제입니다. 실제 비밀값이나 업무 규칙을 포함하지 않습니다.

```json
{
  "version": 1,
  "functions": [
    {
      "id": 2,
      "args": 2,
      "body": {
        "op": "add",
        "left": { "op": "arg", "index": 0 },
        "right": { "op": "arg", "index": 1 }
      }
    }
  ]
}
```

제품 코드에서는 유효한 A/B/O 클라이언트 인스턴스의 `InvokeServerPolicy` 메서드로 이 ID를 호출합니다. 반환값은 업무 결과이며 서버의 세션·라이선스·게시 권한을 대신하는 승인 토큰이 아닙니다. 서버에 정책을 등록하는 것만으로 기존 Delphi 함수가 변경되지는 않습니다. 이전 로컬 계산을 새 호출로 바꿀 지점은 제품 개발자가 명시해야 합니다. 기본 정책에는 사용자 함수가 없으므로 함수 2를 자동 호출하지 않습니다.

연산은 검증된 정수식 IR만 지원합니다. JavaScript 실행, 임의 Delphi 번역, 파일·네트워크 접근 또는 클라이언트가 요청에 넣은 코드 실행은 지원하지 않습니다. 32비트 연산 규칙과 최대 단계 수는 정책 엔진의 기존 제한을 따릅니다. 인수와 결과는 인증된 클라이언트가 알 수 있으므로 입력·출력까지 숨기는 방식으로 설명하지 않습니다.

## 인증과 실패

각 호출은 현재 서버 정책 식별자, 함수 ID, 인수, 역할과 세션에 연결합니다. 일회용 도전값에 서명하여 요청을 확정하고, 만료·재사용·인수 변경·다른 역할·등록되지 않은 함수·폐기된 세션은 거절합니다. 권한은 호출 시 다시 검사하며, 서버 정책 바이트코드나 복호화 키를 반환하지 않습니다. 실패 시 클라이언트에서 같은 계산을 로컬로 우회 실행하지 않습니다.

서버 IR은 순수 계산이므로 호출 결과를 잃었다고 업무 변경이 실행된 것으로 간주하지 않습니다. 결제·파일 변경처럼 별도 부작용이 있는 업무 API로 확장하려면 해당 업무의 서버 권한과 중복 처리 규칙을 따로 설계해야 합니다.

## 운영 전 검증

새 Native 코드는 Windows/Delphi에서 다시 빌드해야 합니다. 이 개발 환경의 서버 회귀 검사는 실제 Windows 실행 성공을 뜻하지 않습니다. 기존 v2의 **최종 발급 A 서명 미완성으로 인한 운영 게시 차단**은 유지합니다. 실제 최종 파일의 서명·Windows 시험·승인·명세 연결 전에는 새 고객용 배포 완료로 취급하지 않습니다.
