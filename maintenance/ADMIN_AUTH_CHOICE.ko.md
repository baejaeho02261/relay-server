# GameConnect / GameWeb — 비밀번호 또는 패스키 선택 수정본

## 이번 변경

기준: `GameConnect_GameWeb_Security_1-10_Railway_Fix.zip`.
이 문서가 이전 7~10번 안내의 **패스키 필수 / 첫 등록 서버 승인 필수** 설명을 대체합니다. 다른 보안 기능의 설명은 그대로입니다.

- 로그인: 기존 관리자 비밀번호 또는 등록된 패스키 중 하나로 로그인합니다. 둘 다 제출하지 않습니다.
- 중요 작업: 최근 인증(기본 5분) 확인은 유지합니다. 인증이 오래됐으면 비밀번호 또는 패스키를 선택하여 재인증합니다. 기본 선택은 비밀번호입니다.
- 패스키 등록: 선택 사항입니다. 최근 비밀번호 인증으로 첫 등록/추가 등록/해제를 진행할 수 있습니다. 일반 등록에는 SSH, BAT, 일회용 서버 승인번호가 필요 없습니다.
- 서버 승인 복구: 선택 기능으로 유지합니다. 이를 명시적으로 선택했을 때만 기존 일회용 토큰 절차를 사용합니다. 잘못된 토큰을 무시하고 비밀번호 승인으로 자동 전환하지 않습니다.
- 패스키 선택 후 취소/실패하면 작업은 적용되지 않습니다. 자동으로 비밀번호 인증을 시도하지 않습니다.
- 별도로 설정한 다른 영역의 2인 승인/고유 운영자 식별 정책은 변경하지 않습니다. 비밀번호를 검증된 패스키 신원으로 표시하지 않습니다.

## 그대로 유지

HTTPS / Secure·HttpOnly·SameSite 쿠키 / CSRF / 로그인 시도 제한 / 서버 세션 만료와 폐기 / 패스키 RP·origin·서명 검증을 유지합니다.
Railway 전송 모드, 웹·네이티브 포트, TCP 입장 제한, 무결성·서버 권한 판정, 서명키 분리, 운영 데이터·키는 변경하지 않습니다.
새 패키지나 인증 프레임워크, 로컬 비밀번호 저장 기능은 추가하지 않습니다. 기존 서버 세션 검증 함수를 사용합니다.

**이 정책은 비밀번호만으로도 중요 작업과 패스키 추가를 허용합니다. 비밀번호가 유출되면 그 경로도 사용할 수 있으므로, 패스키만 허용하는 정책과 같은 피싱 저항성을 주장하지 않습니다.**
참고: OWASP Passkey Security Cheat Sheet — https://cheatsheetseries.owasp.org/cheatsheets/Passkey_Security_Cheat_Sheet.html

## 적용

1. 기존 데이터·인증서·키를 보존하고 해당 서버 소스에 `GameWeb` 변경분을 반영합니다. 전체 ZIP은 누적본이며, 변경분 ZIP은 위 기준 ZIP에 대한 차이입니다. 프로젝트 폴더 구조는 유지합니다.
2. 정상 동작 중인 Railway 환경 변수와 포트는 그대로 둡니다. 새 환경 변수를 추가할 필요가 없습니다.
3. 소스 반영 후 Railway에서 해당 변경을 **Deploy**하여 적용합니다. 이 파일 전달로 운영 서버가 자동 변경되지는 않습니다. 기존 `/data` 영구 저장과 백업 상태를 보존하십시오.
4. 브라우저를 `Ctrl+F5`로 새로고침하고 다시 로그인합니다. 새 UI 식별자는 `console-v4-111-auth-choice`입니다. 이전 화면이 남으면 기존 `/ui-refresh` 기능으로 같은 앱 화면만 갱신하십시오.
5. 비밀번호만 사용할 때는 [비밀번호로 로그인]을 선택합니다. 중요 작업에 재인증 창이 나오면 [관리자 비밀번호]를 선택하고 기존 관리자 비밀번호를 입력합니다. 패스키를 선택할 때는 비밀번호 칸을 비워두십시오.

이번 변경으로 Windows A/B/O를 다시 빌드할 필요는 없습니다. **단, 이전 1~10번 Windows 변경에 대해 아직 하지 않은 빌드·실행 시험은 여전히 남아 있습니다.**

## 시험

GameWeb 폴더에서:

```text
npm run test:admin:auth-choice
npm run test:security:all
npm run test:railway
npm run test:uicache
npm run check:ui
python scripts/verify-source.py
```

이번 실행 결과:
- 인증 정책·세션·선택적 서버 복구: 26개 통과.
- 새 로그인/등록/재인증 HTTP 흐름 및 UI 함수: 19개 통과.
- 기존 웹 인증·CSRF·세션·실제 서명 시험: 24개 통과.
- 기존 보안 1~10번 묶음 `test:security:all`: 통과. 새 정책에 맞춰 기존 패스키 필수 기대값을 조정했습니다. 실패 시나리오를 제거하여 통과시킨 것이 아닙니다.
- Railway 웹 시험: 33개 통과. 실제 HTTP 소켓 + 합성 Railway 헤더/준비 상태이며 실제 플랫폼 시험은 아닙니다.
- 단독 관리자 회귀: 17개 통과. 그중 2개는 소스 연결 검사입니다.
- UI 파일 일치·캐시 갱신 시험: 통과.

범위 제한: Linux Node.js 22.16.0에서 실행했습니다. 이 버전은 프로젝트 선언 지원 범위 밖이며 지원 런타임에서 재시험이 필요합니다. JSON 임시 저장소·합성 인증기·실제 ES256 서명을 사용했고, 기존 묶음에는 모의 상태·정적 검사도 포함됩니다. 전체 SQLite 운영 통합, Windows/Delphi 실행, 물리 패스키·실제 브라우저·실제 Railway 배포는 수행하지 않았습니다. DOM 기반 모달 격리 시험은 `jsdom` 미설치로 실행하지 못했습니다. UI 함수 자체는 별도 VM 시험에서 검증했습니다.

배포 완료, A+ 판정, 무조건적인 보안 보증을 의미하지 않습니다.
