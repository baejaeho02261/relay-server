# 등록 데이터 전체 초기화

이 작업은 서버 운영자가 명시적으로 요청한 등록 초기화입니다. 일반 배포와 재시작은 등록 정보를 보존합니다.

## 웹에서 초기화

관리자로 로그인한 뒤 **등록 데이터 전체 초기화** 버튼을 누릅니다. 삭제 대상 건수를 확인하고 `전체 초기화`를 입력한 뒤, 해당 요청에 대한 관리자 비밀번호 또는 패스키 확인을 완료합니다. 다른 작업에 사용한 인증 승인은 재사용할 수 없습니다.

서버는 초기화 요청을 인증 저장소에 먼저 기록하고 새 작업을 차단한 뒤, 실행 중인 작업을 정리하고 재시작합니다. 다음 시작에서 등록 데이터를 비우고 등록 EXE를 정리합니다. 화면에는 서버 연결이 끊어졌다는 이유만으로 완료를 표시하지 않습니다. 다시 로그인하면 같은 작업 ID의 완료 기록을 확인합니다. 웹 버튼을 이용한 초기화에는 Railway 환경변수 변경이 필요하지 않습니다.

웹 요청 후 프로세스는 실행 중인 작업과 저장소를 정리하고 종료 코드 1로 종료합니다. 호스팅 플랫폼의 기존 자동 재시작 정책이 프로세스를 다시 시작해야 합니다. 플랫폼의 재시작 횟수 한도에 도달했다면 운영자가 서비스를 다시 시작해야 합니다. 초기화 요청은 인증 저장소에 남아 같은 ID로 재개되며, 화면은 완료 기록을 확인하기 전까지 완료라고 표시하지 않습니다.

## 운영자 변수로 초기화

운영자가 서비스에 다음 두 변수를 함께 설정한 경우에만 시작 시 실행합니다.

- `COZY_REGISTRATION_RESET_ID`: 새로 생성한 소문자 16진수 64자리 작업 ID
- `COZY_REGISTRATION_RESET_SCOPE`: `ABO_LICENSES_ISSUANCE_OPERATIONS_V1`

서버는 단일 쓰기 잠금을 확보하고 기존 인증 저장소와 감사 체인을 검사한 뒤, 네트워크 리스너와 작업자를 시작하기 전에 초기화를 완료합니다. 중단된 작업은 같은 ID로 재개하며 완료한 ID는 다시 사용할 수 없습니다. 초기화 완료를 확인한 후 두 임시 변수를 제거하거나 빈 문자열로 설정합니다. 이후 배포에서도 새 등록 데이터가 유지됩니다.

초기화 대상은 A/B/O 후보와 운영 선택, 발급한 A, 실행 세션, 라이선스와 일반 요청 영수증, 기기 등록·PC 차단 목록, 무결성 보고와 기준 파일, 배포 명세·시험 조합·운영 작업·메모입니다. 등록된 EXE는 저장소 안의 검증된 파일 이름만 대상으로 삭제합니다.

이 작업은 서버에 등록한 데이터를 삭제합니다. 운영자나 고객 PC에 이미 내려받은 EXE의 바이트나 Cozy VM 보호 상태는 바꾸지 않습니다. 다시 보호하려면 패킹 전 원본을 사용해야 합니다.

Railway 환경변수, 서버 통신·TLS·패키지 암호화 키, 관리자 패스키와 자격 증명 철회, 신뢰 서명자와 철회 기록, 이미 적용한 최소 보안 버전과 보호 강제 조건은 보존합니다. 켜진 무결성 정책은 보존되므로 기준 파일을 지운 뒤에는 새 기준을 등록해야 합니다.

위변조 검증을 끄거나 인증 저널을 삭제하지 않습니다. 초기화는 기존 키와 독립 witness를 사용해 순서를 앞으로 진행하는 인증 기록으로 남깁니다. 감사 이력과 초기화 ID의 사용 기록은 보존하며, 활성 등록 목록은 비웁니다. 새 초기화 저널 형식을 이해하지 못하는 과거 서버 이미지로의 전환은 거부됩니다.

`REGISTRATION_RESET_COMPLETE` 로그는 초기화 대상의 개수가 모두 0이고 복구용 스냅샷 저장과 EXE 정리가 끝난 뒤에만 출력합니다. `REGISTRATION_RESET_ALREADY_COMPLETED`는 같은 작업 ID로 다시 지우지 않았다는 뜻입니다. 오류나 미완료 작업이 있으면 사용자 연결을 열지 않고 중단합니다.
