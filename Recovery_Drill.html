격리 복구 드릴 사용법

사용자가 지정한 DATA_DIR 백업을 임시 디렉터리에 복사한 뒤 실제 서버 저장소·복구 epoch·저널·witness 코드를 실행합니다. 결과는 JSON으로 기록합니다.

결과 범위: 백업 복사본 검사와 합성 회귀시험을 구분합니다. ok: true는 해당 서버 검사들의 성공을 뜻하며, 실제 Windows 기기·CNG·TPM 또는 전체 운영 복구 승인을 뜻하지 않습니다. NOT_TESTED 항목은 그대로 남습니다.

1. 준비

  • 프로젝트에서 지원하는 Node.js와 설치된 서버 의존성이 필요합니다. JSON 저장 방식에도 실제 단일 writer 잠금용 better-sqlite3가 필요합니다.
  • 합성 회귀시험이 운영 TLS 생성 코드를 사용하므로 OpenSSL을 사용할 수 있어야 합니다. CI 키나 Delphi 컴파일러는 이 도구의 실행 조건이 아닙니다.
  • 중지된 서버에서 만든 완전한 DATA_DIR 백업 또는 일관성이 보장된 스냅샷을 준비합니다. 실행 중인 운영 DATA_DIR을 입력하지 않습니다.
  • witness를 제공하려면 DATA_DIR과 별개인 witness 스냅샷 디렉터리를 준비합니다. 복사된 witness만으로 물리적 독립성이나 최신 운영 head가 입증되지는 않습니다.
  • 결과 파일은 두 입력 디렉터리 바깥의 새 파일 경로로 지정합니다. 기존 결과를 덮어쓰지 않습니다.

2. 실제 백업 복사본 검사

입력 예제를 복사하고 실제 절대 경로와 저장 방식을 입력합니다. storageEngine은 백업에 맞게 sqlite 또는 json으로 지정합니다.

{
  "version": 1,
  "backupDirectory": "D:\\OfflineBackups\\GameWeb-DATA_DIR",
  "witnessSnapshotDirectory": "E:\\OfflineBackups\\GameWeb-witness-snapshot",
  "storageEngine": "sqlite"
}

witness 스냅샷이 없으면 witnessSnapshotDirectory 필드를 삭제합니다. 이 경우 격리된 드릴용 witness를 새로 만들어 롤백 거절만 모의 시험합니다.

GameWeb\tools에서 실행합니다. 결과 디렉터리는 미리 만들어 두어야 합니다.

Run_Recovery_Drill.bat backup "D:\Drill\input.json" "D:\Drill\result-001.json" /nopause

Node.js로 직접 실행할 수도 있습니다.

node recovery-drill.js backup "D:\Drill\input.json" "D:\Drill\result-001.json"

원본은 읽기 전용으로 접근하며, 일반 파일의 해시를 실행 전후 비교합니다. 네이티브 조정용 잠금 파일은 복사·해시 비교에서 제외합니다. 심볼릭 링크·하드링크·특수 파일은 거절하며, 서버 listener를 열지 않습니다. 복사된 비밀정보를 포함한 임시 디렉터리는 종료 시 삭제합니다.

3. 합성 selftest

사용자 백업 없이 별도의 테스트 데이터를 만들고 복사·복구하는 서버 회귀시험입니다. 실제 백업 검증 결과로 사용할 수 없습니다. 백업 모드에서도 같은 시험을 독립된 임시 디렉터리에서 보충 실행합니다.

Run_Recovery_Drill.bat selftest "D:\Drill\selftest-001.json" /nopause

node recovery-drill.js selftest "D:\Drill\selftest-001.json"

CLI selftest는 JSON 저장 방식을 사용합니다. 자동 회귀시험 node scripts/test-recovery-drill.js는 합성 데이터로 JSON과 SQLite를 모두 검사합니다.

4. 검사별 의미

검사입력 백업의 복사본합성 서버 회귀시험
저장소 복원·저널·감사체인실제 저장소 로드·작업 조정·감사체인 확인. 손상되거나 불일치하면 실패합니다.생성한 테스트 스냅샷을 복사한 뒤 같은 서버 코드를 실행합니다.
이전 세션 거절백업에서 복원 가능한 B/O 세션 capability가 있으면 실제 복구 epoch 적용 후 거절을 확인합니다. 대상이 없으면 NOT_TESTED입니다.복구 직전 허용되던 테스트 세션이 복구 후 거절되는지 확인합니다.
사용한 라이선스소모 상태·영수증 보존 및 저널의 소모 취소 거절을 확인합니다. 원래 기기에서 서명한 재사용 요청은 NOT_TESTED입니다.새 소프트웨어 RSA 키로 정상 서명한 재사용 요청이 DESKTOP_KEY_USED로 거절되는지 확인합니다.
기기 키 폐기·새 키 재등록원래 기기의 개인 키를 가져오지 않으므로 NOT_TESTED입니다.실제 기기 등록 서비스와 저장소에서 테스트 키 폐기, 기존 세션 종료, 이전 키 거절, 승인된 대체 키 등록을 확인합니다.
witness 롤백 거절제공된 witness 스냅샷과 먼저 대조합니다. 격리 복사본을 진행시킨 후 이전 복사본이 거절되는지도 시험합니다.새 드릴 witness를 진행시키고 이전 전체 데이터 복사본의 거절을 시험합니다.
재시작 후 지속성새 Node.js 프로세스에서 복구 epoch·소모 라이선스 수와 witness의 현재 상태를 다시 확인합니다.

5. 결과 확인

  • backup은 사용자가 제공한 백업 복사본의 결과이고, syntheticRegression은 합성 시험 결과입니다.
  • coverage: "PARTIAL_BACKUP_EXERCISE"와 개별 NOT_TESTED 항목을 함께 확인합니다. 보충 시험이 성공해도 원래 기기 검사가 수행된 것으로 바꾸지 않습니다.
  • originalBackupUnchanged, 제공 시 originalWitnessUnchanged, isolatedCopiesRemoved를 확인합니다. 원본 변경이나 재확인 실패, 임시 파일 삭제 실패는 전체 실패로 기록됩니다.
  • RECOVERY_ROLLBACK_DETECTED가 백업 로드 단계에서 발생하면 제공된 witness와 백업이 맞지 않는 것입니다. 도구는 그 witness를 다시 등록하거나 초기화하지 않습니다.
  • DRILL_CLEANUP_FAILED이면 결과의 cleanupDirectory를 확인합니다. 해당 임시 복사본에는 서버 비밀정보가 남아 있을 수 있습니다.
  • 정상 종료 코드는 0, 검사 실패는 1입니다. BAT의 잘못된 인자 사용은 2입니다. 입력 거절 시에도 CLI는 오류 코드를 JSON으로 출력합니다.

6. 실제 Windows에서 남은 확인

새 기기·새 키의 양성 시험이 별도로 필요합니다. 실제 Windows에서 CNG 명명 키 생성·유지·재시작, 폐기된 키 거절, 승인된 대체 키로 A/B 등록 및 정상 인증 경로를 확인해야 합니다. TPM 정책을 사용한다면 실제 TPM 키 증명·credential activation·재설치/TPM 초기화 후 재등록도 따로 확인해야 합니다.

이 도구의 RSA 테스트 키와 PE fixture는 서버 동작을 재현하는 합성 입력입니다. Windows 실행 파일, BAT의 실제 Windows 실행, 기존 장치에서 새 장치로의 전환, CNG 키의 비내보내기 성질 또는 물리적 TPM의 성공 증거를 생성하지 않습니다. 라이선스 자동 이월도 증명하지 않습니다.
