# 선택형 소유 포인터 그래프 V2

`Cozy.PointerGraph.pas`의 기존 `CozyPointerGraphBytes`는 V1 DAG 검증과 기존 골든 바이트를 유지합니다. 기존 `SEALED_API_ARENA` 측정과 서버 승인 계약도 V1 그대로입니다.

새 V2는 프로그램이 직접 소유하고 명시적으로 등록한 업무 구조를 위한 별도 계약입니다. 실제 주소를 따라가거나 다른 프로세스를 읽지 않습니다. 배열 순서에 관계없이 안정 ID와 포인터 슬롯 오프셋으로 정렬하며 프로세스 주소는 입력 필드가 아닙니다. 포인터를 이동했다고 ID가 변하면 안 됩니다.

## 1. 명시적 상태 전이

한 소유 컨텍스트에 `TCozyPointerGraphHistory` 하나를 유지합니다. 동일한 소유·수명 잠금 안에서 스냅샷을 만들고 `Accept`를 호출합니다. 실패한 호출은 보관 중인 이전 상태를 변경하지 않습니다. `Capture`는 복사본을 반환합니다.

- 최초 스냅샷: revision 1, 모든 노드 generation 1, 각 노드에 `pcRegister`.
- 상태 유지: revision을 정확히 1 증가시키고 변경 목록은 비웁니다.
- 참조 변경: 살아 있는 노드의 출력 간선을 바꾸면 해당 노드에 `pcRebind`가 필요합니다.
- 폐기: generation을 유지하고 Alive를 False로 바꾸며 `pcRetire`를 명시합니다. 해당 노드에 연결된 간선은 제거해야 합니다. 살아 있는 자식의 소유자는 폐기할 수 없습니다. 간선이 바뀐 다른 출발 노드에는 `pcRebind`가 필요합니다.
- 재등록: 이전 스냅샷에서 폐기된 노드만 `pcReregister`로 되살릴 수 있습니다. generation은 정확히 1 증가해야 합니다. 새로운 소유자·규격은 재등록 때 명시합니다.
- 폐기된 노드는 묘비 기록으로 계속 포함합니다. 기록 삭제, 세대 역행·재사용, 살아 있는 노드의 암묵적 재등록, 소유자 교체, 불필요한 변경 선언은 거절합니다.

노드의 소유자 ID와 소유자 generation, 간선의 출발·도착 generation을 각각 검사합니다. 루트 ID는 해당 history 수명 동안 고정되며, 루트는 계속 살아 있어야 합니다. 전체 컨텍스트가 끝나면 history와 실제 소유 객체를 함께 종료합니다. 노드와 묘비를 합쳐 최대 4,096개입니다. 상한에 도달하면 등록을 거절하며 오래된 묘비를 자동 삭제하지 않습니다. 새로운 history는 새로운 컨텍스트이므로 프로세스 재시작·디스크 롤백을 막는 영구 서버 증거로 취급하면 안 됩니다.

## 2. 순환 참조

`CozyOwnedPointerGraphBytes`와 `COZY-OWNED-POINTER-GRAPH-V2`를 명시적으로 선택해야 합니다. 참조 간선에는 순환과 자기 참조를 허용하지만, 소유 관계는 단일 살아 있는 루트에 연결된 깊이 16 이하의 비순환 트리여야 합니다. 모든 살아 있는 노드는 루트에서 참조 간선으로 도달 가능해야 합니다.

최대 노드·간선은 각각 4,096개, 노드 span은 1..1,048,576바이트, 포인터 슬롯 폭은 4 또는 8바이트입니다. 한 출발 노드의 슬롯은 겹칠 수 없습니다. 순환 참조 탐색은 재귀 호출 대신 최대 노드 수 크기의 큐를 사용합니다. V1의 순환 거절을 느슨하게 바꾸지 않았습니다.

정규 바이트는 계약 접두어, uint64 revision, 루트 ID·세대, 노드·간선 수, 소유 깊이 및 정렬한 레코드를 little-endian으로 포함합니다. 같은 논리 ID·내용·revision이면 배열 순서를 바꿔도 같은 바이트를 얻습니다. 주소 변경 자체는 입력에 포함하지 않습니다. JS에서는 uint64 revision을 정확하게 보존하기 위해 10진 문자열로 받습니다.

## 3. 연결 예시

기존 API 측정은 변경하지 않습니다. 업무 객체 쪽에서 소유 컨텍스트를 만들고 안정 ID를 부여한 다음, 실제 객체·콜백 연결을 바꾸는 지점과 같은 잠금 안에서 다음 스냅샷 및 변경 목록을 구성합니다. `Accept`가 반환한 정규 바이트를 해당 업무 계약의 암호학적 해시에 사용합니다. 일반 CRC만으로 인증하지 않습니다.

Relay의 `services/integrity/peace.pointer-graph-lifecycle.js`는 동일한 계약을 검증하는 별도 모듈이며 `History`, `transition`, `bytes`를 제공합니다. 기존 측정 API가 V2를 자동 신뢰하도록 변경하지 않았습니다. 구체적인 업무 객체의 허용 규격과 서버 승인 범위는 호출자가 명시해야 합니다.
