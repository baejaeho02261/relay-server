# 원본 명세와 보호 결과 등록

배포 명세는 A/B/O 세 파일의 최종 SHA-512와 실행 연결 규격을 묶습니다. 패킹 결과는 원본과 파일 내용이 다르므로 원본의 명세 ID나 EXE 승인 JSON을 그대로 사용할 수 없습니다. 서버는 이 검사를 유지합니다.

## 웹에서 보호 결과 등록

라이선스 관리 또는 패킹 결과의 **보호 결과 등록**을 엽니다. 같은 패킹 작업에서 받은 A/B/O EXE와 각 최종 파일에 대한 새 `.approval.json`을 선택합니다. 새 승인 JSON은 기존 배포용 키로 만들 수 있습니다. 개인키를 웹에 업로드하지 않습니다.

화면은 선택한 파일의 역할·SHA-512·크기와 승인 JSON의 역할·버전·SHA-512를 먼저 확인합니다. 서버는 저장된 패킹 작업의 세 결과 해시와 원본 후보의 명세 연결을 확인합니다. 원본 명세의 배포 정보·도구 정보·소스 해시·보안 버전을 유지하고 현재 보안 정책의 해시와 보호 결과 해시를 결합해 새 명세를 계획 등록합니다. 원본 명세는 변경하지 않습니다.

화면은 새 명세 ID로 최종 세 파일을 후보 등록하고 같은 명세의 등록을 완료합니다. 이 경로에서는 기존 `spec.json`이나 배포 명세를 로컬 도구로 다시 만들거나, 원본 명세 ID를 복사할 필요가 없습니다. 최종 승인 JSON의 버전을 사용하므로 승인 때 선택한 버전과 업로드 버전이 일치합니다.

등록 후에는 **서버 보안 · 배포 운영**에서 보호된 A/B/O 세 후보로 **조합 검증 → 검증한 A/B/O 조합 운영 게시**를 진행합니다. 후보 등록은 운영 게시를 자동으로 수행하지 않습니다. Windows 동작 확인은 별도로 수행합니다. 서버의 서명 유효성·무결성·현재 보안 정책 검사는 유지합니다.

## 파일과 기록의 유지

패킹 결과 다운로드가 만료돼도 이미 받은 파일과 서버의 패킹 기록이 남아 있으면 등록할 수 있습니다. 일반 배포·재시작은 패킹 기록을 보존합니다. 등록 데이터 전체 초기화는 원본 후보·명세·패킹 기록을 삭제합니다. 초기화 전에 만든 보호 파일만으로는 새 변환 기록을 만들 수 없습니다.

파일을 다시 패킹하거나 편집하면 해시가 달라집니다. 이 화면은 패킹 작업에 기록된 정확한 결과만 받습니다. 원본 명세의 보안 버전이 현재 하한보다 낮거나 원본 조합이 폐기된 경우 자동 명세 생성도 거절합니다. 보안 버전 숫자를 자동으로 올려 과거 소스를 최신 보안 배포로 바꾸어 표시하지 않습니다.
