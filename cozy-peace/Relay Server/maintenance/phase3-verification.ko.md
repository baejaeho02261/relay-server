# 사용자 정의 서버 연산과 자체 포인터 관계 검증

이번 단계는 등록한 사용자 정수식의 실제 인증 호출 경로와, 프로그램이 소유한 포인터 구조의 검증 범위를 추가합니다. 기존 서버 정책 연결 v2와 키 없는 발급 형식을 유지합니다. 기존에 배포한 실행 파일은 새 소스로 자동 교체되지 않습니다.

## 서버 연산

사용법은 `server-operations.ko.md`를 참조하세요. 새 A/B/O Native 클라이언트의 `InvokeServerPolicy` 메서드는 등록한 함수 ID·인수를 서버 정책과 현재 세션에 연결하여 호출합니다. 실제 암호화된 전송 경로에서 서명·일회용 도전값·기기·파일·정책·현재 권한과 필요한 라이선스를 검사합니다. 예약 함수 1, 없는 함수, 다른 역할·정책, 변경한 인수, 오래된 권한과 재사용 도전값은 거절합니다.

연산은 최대 8개 Int32 인수와 기존 제한된 정수식 IR을 사용합니다. RSA 증명은 기존 검증 워커를 거치고, 최대 1,024단계의 순수 연산은 권한 재확인과 함께 제한된 서버 처리 구간에서 실행합니다. 응답에는 결과 정수와 공개 호출 식별자만 포함하며, 정책 코드·키·새 세션 권한을 반환하지 않습니다. 실패 시 로컬 계산으로 우회하지 않습니다.

기본 정책은 사용자 함수를 자동 호출하지 않습니다. 기존 Delphi 업무 로직을 서버로 옮기려면 지원하는 정책식으로 정의하고 해당 제품 코드의 호출 지점을 명시적으로 바꿔야 합니다. 입력·출력은 인증된 호출자가 볼 수 있습니다. 결제나 파일 변경처럼 부작용이 있는 임의 업무를 이 계산 API로 실행하지 않습니다.

## 포인터 검증 범위

일반·복수·계층 연결을 노드와 간선으로 표현하는 제한된 자체 그래프 검증을 추가합니다. 노드 수·간선 수·깊이·수명 세대·범위·중복·순환·연결되지 않은 노드를 검사하고, 주소를 제외한 정규화된 구조를 해시합니다. ASLR로 달라지는 실제 주소를 서버 기준 해시로 고정하지 않습니다.

실제 런타임 연결 범위는 읽기 전용 API 저장소, 그 항목의 소유 슬롯과 원래 함수 대상 관계입니다. 별도로 등록한 소유자와 일치하는지 확인한 뒤 메모리 영역·슬롯 번호·디코딩 대상·원래 모듈 관계를 검사합니다. 임의 주소를 따라가거나 다른 프로세스의 메모리를 읽지 않습니다. 동적으로 바뀌는 모든 힙 포인터나 CPU 레지스터 전체를 검사하는 기능으로 설명하지 않습니다.

새 파일은 확장 측정 버전을 알리고 포인터 그래프 결과를 서명된 자체 보고에 포함합니다. 서버의 기대값은 승인한 파일의 빌드 계약에서 얻으며, 클라이언트가 보낸 슬롯 개수를 기준으로 삼지 않습니다. 새 버전 파일이 측정 완료를 주장하면서 필수 그래프를 누락하거나 불일치하는 경우에는 서명 확인 후 해당 조합의 권한을 폐기합니다. 취소·읽기 실패는 검증 성공이나 권한 갱신으로 처리하지 않으며, 이를 실제 변조가 입증된 것으로 표시하지 않습니다. 이전 파일에는 새 검사를 완료한 것으로 표시하지 않습니다. 자체 보고는 하드웨어 증명이 아닙니다.

## 검증과 운영 제한

서버 검사는 격리 저장소·실제 서명·실제 암호화 전송과 A/B/O 권한 경로를 사용합니다. 그래프는 정규화 벡터와 잘못된 관계·범위·수명·버전 하향 시도를 검사합니다. Native 예제와 시험 프로젝트는 전체 소스에 포함합니다.

**실제 Windows/Delphi 컴파일·실행·종료·잔여물·Authenticode 서명은 이 환경에서 NOT_RUN입니다.** 준비된 Native 시험 소스와 Linux 회귀 검사를 실제 EXE 실행 결과로 대체하지 않습니다. 최종 발급 A 서명이 미완성이므로 v2 운영 게시의 `COZY_SERVER_POLICY_FINAL_ISSUED_SIGNING_REQUIRED` 차단은 유지합니다. 이번 작업은 그 차단을 해제하거나 기존 등록 데이터를 초기화하지 않습니다.
