Floating-point JSON differential

This test compares the existing JavaScript receipt canonicalization with an independent Python oracle. The oracle rounds exact decimal fractions to binary64 and searches decimal rounding intervals using integer arithmetic. It does not call a host floating-point formatter. Expected SHA-512 digests come from the pure-integer Python hash reference.

Server/reference test

From the extracted project root, with Node.js and Python 3 available:

node Relay Server/tests/cryptography/peace.test-float-canonicalization-14.js

The local verification covers 450 cases: 291 admitted protocol bodies, 159 rejected bodies, and 433 direct numeric-format comparisons. The 143 unsafe finite values checked only for formatting are explicitly labeled FORMAT_ONLY_PROTOCOL_REJECTED. A server/reference pass reports nativeOutcome: "NOT_RUN".

Manual Windows comparison

  1. Open cozy.FloatJsonProbe.dproj in RAD Studio. Select Win64 / Release and build this test project. The shared manual properties isolate its output and DCUs. This step does not build A/B/O.
  2. Run the command below from the project root on that Windows machine. The runner requires a real AMD64 PE executable, creates the numeric corpus, runs the probe, and removes its temporary inputs.
node Relay Server/tests/cryptography/peace.test-float-canonicalization-14.js --native-json Railway/build/tests/manual-ide/cozy.FloatJsonProbe.exe

The probe uses production ParseProtocolObject, EncodeRequestEnvelope, and SHA512Bytes. It measures parser decisions, Double bits, serialized body/envelope bytes, and their hashes. The runner independently canonicalizes the observed Delphi wire through Python and JavaScript, then compares exact UTF-8 bytes and receipt hashes. The product does not contain a Delphi receipt canonicalizer, so this result is labeled as Delphi wire normalization followed by server canonicalization.

Numeric scope

The server JSON boundary admits finite binary64 fractions, signed zero, and subnormal values; values that round to unsafe integers are rejected. Tiny decimal inputs can round to zero. NaN, Infinity, malformed JSON numbers, and overflowing values are rejected. Action schemas impose additional integer/type requirements on their own fields. Delphi RTL conversion parity remains subject to the native run above. The corpus covers decimal and binary powers and neighbors, normal/subnormal transitions, exact halfway rounding, notation boundaries, long lexemes, seeded bit patterns, nested arrays, and UTF-16 key ordering.

No production serialization rule was changed. Native compilation and execution have not been performed in the Linux preparation environment.
