IDE 사전 빌드 · Windows 실행 시험

명령줄 Delphi 컴파일러를 사용하지 않습니다. IDE가 정상적으로 빌드한 시험 EXE를 실행하고, 실제 결과·SHA-512·로그를 저장합니다. 이 패키지 작성 환경에서는 Windows 시험을 실행하지 않았습니다.

1. 기본 Delphi 시험 빌드

  1. RAD Studio에서 cozy.ManualNativeTests.groupproj를 엽니다.
  2. 플랫폼 Win64, 구성 Release를 선택하고 IDE에서 Build All을 실행합니다. 명령줄 빌드 BAT를 실행하지 않습니다.
  3. 생성된 시험 EXE는 이 폴더의 bin에 모입니다. DCU는 units/각 시험 이름/Win64/Release로 분리됩니다.
  4. 오버레이 시험은 A/B/O 빌드에 사용한 정상 Cozy.imgui/obj/Win64/cozy.game_imgui_bridge.o가 필요합니다. 파일이 없다면 해당 프로젝트의 정상 ImGui 준비를 먼저 완료합니다. IDE 라이선스 또는 C++ 도구가 허용하지 않는 빌드는 건너뛰며 성공으로 기록하지 않습니다.

Cozy.DeviceKeyContractProbe는 네이티브 핸들 부분 생성 실패·정리·재시도 계약을 시험하는 독립 실행 파일입니다. 실제 영구 장치 키나 TPM 키를 만들지 않습니다. 그룹에 포함된 Cozy.DeviceIdentityProbe는 별도 실제 장치 시험용이며 기본 실행 도구는 실행하지 않습니다.

2. 선택: Windows SDK ABI 대조

cozy.NativeAbiSdkProbe.vcxproj를 Visual Studio에서 열고 Release / x64로 IDE 빌드합니다. 필요한 SDK·도구 집합 재설정은 실제 설치된 버전으로 하세요. 같은 bin/cozy.NativeAbiSdkProbe.exe가 생성됩니다. 없으면 SDK 대조만 NOT_RUN이며 Delphi 자체 레이아웃 시험과 구분됩니다.

3. 선택: 실제 D3D11에 대한 오류 주입 시험

이 시험은 실제 시험 소유 창·D3D11 장치를 만든 뒤 시험 전용 브리지에서 Create/Resize/Present 오류 반환을 주입합니다. 실제 GPU 드라이버 손상·물리 장치 제거 시험을 대신하지 않습니다.

  1. C++Builder IDE에서 시험 전용 C++ 정적 라이브러리 프로젝트를 gpu-fault 폴더에 만듭니다. 플랫폼은 classic Win64입니다. Win64 Modern / bcc64x / COFF 출력은 사용할 수 없습니다.
  2. 프로젝트 기본 소스와 별도로 이 폴더의 cozy.gpu-fault/cozy.game_imgui_fault_test.cpp를 추가합니다. 이 파일에만 GAME_IMGUI_FAULT_TESTS가 정의되어 있습니다.
  3. Release 설정에서 예외·RTTI를 끄고, 해당 C++ 파일의 추가 컴파일 옵션에 다음 옵션을 적용합니다. 이는 기존 정상 브리지 빌드와 같은 네이티브 옵션입니다.
    -std=c++11 -O2 -fno-exceptions -fno-rtti -fno-builtin -fno-use-cxa-atexit
  4. Include 경로에 실제 프로젝트의 Cozy.imgui/vendor, Cozy.imgui/cozy.vendor/backends, Cozy.imgui/bridge와 설치된 classic Win64 C++Builder의 표준 Windows SDK/CRT 경로가 있어야 합니다. BDS 아래 include, include/dinkumware64, include/windows/crtl, include/windows/sdk를 사용합니다.
  5. IDE에서 이 C++ 파일을 Compile하여 cozy.game_imgui_fault_test.o를 만듭니다. 중간 출력 폴더에서 생성된 실제 ELF 오브젝트를 cozy.gpu-fault/cozy.game_imgui_fault_test.o에 둡니다. 라이브러리나 COFF 파일의 확장자만 바꾸면 안 됩니다.
  6. cozy.OverlayGpuFaultProbe.dproj를 RAD Studio에서 열어 Win64 Release로 빌드합니다. 빌드 전 시험 전용 ELF 감사가 20개 정상 ABI와 3개 시험 함수, 미해결 외부 심볼 및 정적 생성자 부재를 확인합니다. 이 감사는 컴파일러를 실행하지 않습니다.

시험 오브젝트를 정상 cozy.game_imgui_bridge.o로 덮어쓰거나 A/B/O에 연결하지 마세요. 정상 배포 오브젝트 감사는 시험 함수를 계속 거절합니다. C++Builder IDE에서 이 구성의 컴파일이 지원되지 않으면 해당 시험은 NOT_RUN으로 유지합니다. 라이선스 제한을 우회하지 않습니다.

4. 실제 시험 실행과 결과 확인

  1. Relay Server/tools/Run_Manual_Windows_Tests.bat를 실행합니다. PowerShell 7 x64와 Node.js가 필요합니다. 기본 probe 폴더는 이 폴더의 bin입니다.
  2. A→B→O 전체 실행도 시험하려면 YES를 입력하고 완성된 Release A/B/O 경로와 실제 버전을 입력합니다. 이 선택에만 OpenSSL 및 준비된 Relay Server Node 의존성이 필요합니다.
  3. 도구는 새 임시 디렉터리, 임시 승인키, localhost TLS 서버를 만듭니다. 기존 운영 서버·정책·개인키·데이터를 사용하지 않습니다. 실제 실행/라이선스/오버레이 READY/부모 파일 삭제/종료/세션 정리를 검증합니다.
  4. 결과는 BAT 옆 manual-날짜-ID-results.json, 입력은 manual-날짜-ID-inputs.json, 로그와 검사한 probe 복사본은 manual-날짜-ID에 저장됩니다. 임시 서버와 키 자료는 종료 시 정리합니다.

입력 JSON의 probes에 개별 시험 이름과 절대 경로를 지정하여 다른 폴더의 시험 EXE를 사용할 수 있습니다. 입력 재사용: Run_Manual_Windows_Tests.bat "입력 JSON 전체 경로".

MANUAL_EXECUTION은 실제 실행한 행만 설명합니다. 미빌드는 NOT_RUN, 일부 생략은 PARTIAL, 오류는 FAIL입니다. 실행 전후 입력이 바뀌면 실패합니다. 결과는 운영 게시 승인서가 아닙니다. 물리 DPI/다중 모니터, GPU/드라이버 상태 전환, RDP 재접속, 실제 TPM 제조사 증명은 별도로 남아 있습니다.
